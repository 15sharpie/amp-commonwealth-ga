# Troubleshooting

Every problem below came up while getting this template working on AMP 2.8 with Wine. Most of them
show up in the instance console, in `amp-wine-setup.log`, or as a map stuck at `STARTING`.

| What you see | Cause | Fix |
|---|---|---|
| AMP pops up `Failed to update 15sharpie/amp-commonwealth-ga:main. Check the Deployment Log for more details.` (about once an hour), and the Deployment Log only shows `Cloning into '15sharpie-amp-commonwealth-ga-main'...` | AMP keeps its own copy of each template repository and updates it in place every hour. That update fails after the repository's history has been rewritten, which happened on 2026-11-20 (to correct the commit author). The repository itself is fine. | Under **Configuration → Instance Deployment → Configuration Repositories**, remove `15sharpie/amp-commonwealth-ga:main`, save and click **Fetch Latest** (AMP deletes its old copy). Then add it back, save and click **Fetch Latest** again. Existing instances aren't affected. |
| `control-server: CPU ISA level is lower than required`; AMP says the app failed to start twice | The release build needs x86-64-v3 (AVX2). The VM's CPU type hides it. | Use a CPU type of `x86-64-v3` or `host`, then fully stop and start the VM. |
| `wine: could not load kernel32.dll, status c0000135`; `drive_c/windows/syswow64` is empty | The Wine prefix never got its 32-bit half. `wineboot` opened the Wine Mono install prompt, which waits forever under Xvfb. | Fixed in `amp-wine-setup.sh` (it creates the prefix with `WINEDLLOVERRIDES="mscoree,mshtml="` and rebuilds a prefix with an empty `syswow64`). Run **Update**. |
| Prefix setup hangs; `Failed to open RpcSs service` in the log | Same Mono prompt. The RpcSs errors are a side effect. | As above. |
| Map stuck at `STARTING` and the player sits on a loading screen; no files in `logs/<instance>/` | The game crashed about 3 seconds in (`Unhandled page fault … in GlobalAgenda.exe`) because the server hook never loaded, and `winedbg` then held the dead process. Under WineHQ Wine nothing loads `version.dll`. | Use the `dinput8.dll` hook. The template installs it, removes `version.dll`, and adds a `dinput8` override in the prefix. |
| `PhysXLoader.dll` missing; game exits early | The game's prerequisites aren't installed in the prefix. | `amp-wine-setup.sh` runs `PreReqs/vcredist.exe /Q` and `PreReqs/physx.exe /passive /norestart`. Check `amp-wine-setup.log` for `check: PhysXLoader.dll present`. |
| `.NET 3.5` and `DirectX` installers time out or crash in `amp-wine-setup.log` | They don't install under Wine. | Expected. The server doesn't need them; they're tried once and then skipped. |
| `no such table: map_game_info`; `table ga_queues has no column named team_policy`; matchmaking finds no queues | The database was created before 0.1.59 without the baseline content. | Stop the server, move `server.db`, `server.db-wal` and `server.db-shm` aside, make sure `dbbase/base.db` exists, and start it. A fresh database is built from the baseline. |
| Node: players get kicked back to the login page when they start a mission | The node's hook DLL doesn't match the master's, so the master won't place players on it. | Set `"update_mode": "apply"` in the `node` block and restart. |
| Node: the master spawns a map on your node, but the player never arrives and it stops after about 2 minutes with `reason=last player left` | The player's game couldn't reach the node over UDP. | Forward UDP 9002–9020 to the AMP machine on the **same internet connection the node uses to reach the master** (the master advertises the address it sees). With two internet connections, check which one carries outbound traffic. |
| Players don't appear in AMP's user list | Standalone: the patterns match the chat lines (template v6+). Node: they match the `[node] player joined … name='…'` lines, which start with release 0.1.61. A node only lists players in maps it's hosting. | Check the console for those lines. Node: the master hands out its own build, so the node gets 0.1.61 once the master runs it. Instances made before 2026-11-20 keep their old patterns. |
| AMP's Analytics page counts sessions but shows no player names, and the country as unknown | Names: AMP stores players anonymously unless **Configuration → Security and Privacy → Store user-specific data** is on (sessions recorded before you turn it on stay anonymous). Country: AMP needs each player's IP from the console. A node never sees it (the master doesn't send it). | Turn on Store user-specific data if you want names; it then keeps the names of everyone who plays on your server for the retention period. The country can't be shown on a node. |
| AMP never lists the apps after adding the repo | The repo entry is wrong, or AMP hasn't fetched it. | The entry is `15sharpie/amp-commonwealth-ga:main`. Click **Fetch latest** after saving. |
| Start does nothing on a brand-new instance | The app has never been updated, so there's nothing to start. | Run the first **Update** from the panel. |
| Node app: the server won't start | The node settings are missing or malformed, so the start-up step stops the start on purpose. | Fill in Node ID, Node key (64 hex characters) and Master address (host:port) under **Configuration → Global Agenda → Node**. `amp-node-config.log` says which one is wrong. |
| Standalone app with Server role "Node": the node settings don't show up in `control-server.json` | The start-up step skipped them. | Read `amp-node-config.log`: it says why (missing or malformed setting, `jq` missing, or `control-server.json` isn't plain JSON, for example after `//` comments were pasted in). |
| Node: **Master Link** on the Status page is red | The node has no open connection to the master (master down, network, or a rejected key), or the indicator isn't running. | Check the console for `[NodeLink]` lines. `amp-master-link.log` records each change with a time, and why the indicator stopped if it did. No log at all: `control-server.json` has no `"role": "node"` / `master_addr`, or the instance was made before 2026-11-20 and lacks the `Start Master Link Indicator` start-up step (existing instances don't pick up new template steps yet; see [TODO.md](../TODO.md)). |
| Node: **Master Link** stays red after the master is back up | `control-server` 0.1.62 and older stop retrying after a connection attempt times out (the console's last `[NodeLink]` line is `connect to master timed out`). | Wait: the Master Link script restarts `control-server` within about 3 minutes of the master answering, once no map is running. `amp-master-link.log` says what it's waiting for. If it says `not restarting it again`, check the node key and master address, then restart the server from the panel. Instances made before this was added need a template update first. |
| Two Global Agenda instances on one machine: the second one's ports differ from the docs, or its maps fail to start | AMP moves a new instance's ports when another instance already has them, and both apps copy AMP's ports into `control-server.json` on every start. But both instances still default to the internal IPC port 9010, which isn't one of AMP's ports. | Forward the ports the Status page lists. In one instance's `control-server.json` (File Manager), set `ipc_port` to a free port such as 9040, then restart it. |
| Standalone app: ports changed in `control-server.json` change back on the next start | The `Apply Port Settings` start-up step sets `tcp_port`, `chat_port` and `udp_port_range` from AMP's ports every time, so AMP's ports win. | Use the ports AMP shows on the Status page. `amp-port-config.log` records each change it made. |
| Node made from the standalone app: Login and Chat ports are red, no Master Link | That app's Status page lists the standalone ports. AMP's panel can't change an instance's ports. | Harmless. For the node Status page, create the instance from **Global Agenda (Commonwealth Node)**. |

## Getting more detail

- **Game process output:** the control server sets `WINEDEBUG=-all` for maps, so Wine errors
  barely show. Tracing a launch needs a shell inside the instance's container on the AMP host: run
  the same command line the control server uses (it's in the source, `InstanceSpawner.cpp`) with
  `WINEDEBUG=err+all,+loaddll`, and time-limit it.
- **Per-map logs:** set `"enabled_channels": ["debug"]` in `control-server.json` and restart. Each
  map then writes `logs/<instance>/debug.txt`.
- **Console history:** AMP's console only keeps the last 40 lines, and `[dbperf]` lines take up
  most of them. Read it soon after the event, or poll it.
